# M8 metrics cost on the UDP responder: 2026-10-14 (Linux, WSL2)

The Linux pair of measurement M8 (WP3.5 item 7), run by the lead at the merge of `wp35a` on the same day and the same workstation as the Windows run (`2026-10-14-m8.md`, which describes the method). Acceptance: the metrics cost at most 2 percent of throughput, the p99 unchanged within noise, zero allocations on update.

## Summary

| Workers | Pairs | Median QPS change (on against off) | Median p99 change | Result |
|---|---|---|---|---|
| 1 | 10 (two sets) | -2.20 % (set 1: -2.60 %, set 2: -1.88 %) | +1.7 % | At the limit, within the noise of WSL2 (below) |
| 4 | 5 | -1.37 % | +1.3 % | PASS |

- Zero allocations: `cargo test --release --test zero_alloc` passes on Linux (a million `inc`, `add` and `observe` calls on one thread, then on four threads, allocate nothing).
- The first pair of the first one-worker set is an outlier (QPS -8.61 %, p99 +170 %): its run with the metrics on hit a scheduling stall; every other pair of both sets is within -2.75 % and +0.57 %. Without that pair the ten-pair median is -1.88 %.
- Accepted by the lead: the cost sits at the 2 percent line on a single worker inside a WSL2 virtual machine, whose noise exceeds the effect measured; the Windows run on the same machine measured about 52 ns of server CPU per packet (+0.9 %). The measurement is repeated on bare-metal Linux when the self-hosted runner exists (see the status file).

## Observations

- Linux answers about 175,000 queries per second on one worker against 162,000 on Windows, and 880,000 to 970,000 on four workers against 480,000: the Linux socket path is cheaper, so the fixed cost of the metrics (two clock reads, one counter update, one histogram observation) is a larger share of a shorter packet time, which is why the Linux percentage runs higher than the Windows one for the same work.
- The p99 of the one-worker runs drifts between sets (1.7 ms in the clean set, 2.8 to 3.9 ms in the first), with the metrics on and off alike: the virtual machine, not the metrics.

## Conclusion

PASS at four workers (-1.37 % QPS, p99 +1.3 %); at one worker the median over ten pairs is -2.20 %, -1.88 % without the stalled pair, at the limit inside WSL2 noise, accepted by the lead and to be repeated on bare-metal Linux. Zero allocations on Linux as on Windows.
