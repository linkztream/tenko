# M9 idle RSS of `tenko serve --roles controller`: the static musl binary of `main`, 2026-10-17 (Linux)

Verdict: PASS (idle VmRSS 75.44 MiB at most against 95.37 MiB)

Measurement M9 of the Phase 1 plan (section 8): idle RSS below 100 MB (OPS-15), 10 minutes idle after the data creation. This is the first run by the procedure of [../README.md](../README.md) as it reads since this date: on Linux it builds and measures the static musl binary (`--target x86_64-unknown-linux-musl`), the binary that the release workflow ships, and no longer a glibc build of the same source, whose allocator keeps the start-up peak ([2026-10-16-m9-linux-memory.md](2026-10-16-m9-linux-memory.md), deviation 70 of [phase-1-exit.md](../../../docs/plans/phase-1-exit.md)). One run, 600 s idle, inside WSL2.

## Source and build

- Source: `git archive 701a5ef1168b51105d9be994328a27005f4d0b0c` (`main`), extracted to an ext4 directory in WSL, with the `ui/dist` built from the same commit (`npm ci && npm run build`) copied in. SHA-256 of the archive `623ee8058516c8fe`, of the `ui/dist` tar `c94ac275b88be173` (prefixes). The commits of this branch change no crate, so the binary is that of the branch too.
- Build: `cargo build -p tenko --release --locked --target x86_64-unknown-linux-musl` (1 min 57 s). `tenko` is 124,393,152 bytes (118.6 MiB), `static-pie linked`, not stripped; SHA-256 starts `b46b9a131ec9bd2e`.
- The script is `m9-idle-rss.sh` of this branch (the commit that adds this file), which also records the linkage of the binary.

## Method

As in [../README.md](../README.md): a fresh data directory, the shipped defaults (`internal_ca` TLS, profile `home`, `[kek] provider = "platform"`, which falls back to a plain key file for a non-root user in WSL), `hibp.online = false`, first-run setup and login with the CLI, 200 prefixes (one /8, four /16, 195 /24) with `tenko prefix create`, 600 s idle with a sample every 30 s, then `SIGTERM`.

```
bash m9-idle-rss.sh --binary <dir>/tenko-701a5ef --port 18444 --outdir <dir>/raw     (inside WSL, as user plm)
```

Nothing else ran on the machine during the run.

## Verdict

M9 is met on Linux by the binary that ships: idle VmRSS at most 75.44 MiB (79.1 MB) after the data creation, 19.9 MiB under 95.37 MiB. Phase 1 exit criterion E11 (OPS-15) on Linux rests on this file; `e11_ops_15_the_newest_m9_run_on_linux_passes` reads it.

## Caveats

- Linux was measured inside a WSL2 VM, not on bare metal.
- The data set is CLI-created prefixes, not an import, and only the controller role exists, as in every M9 run so far.
- M9 on the container image and on a cluster member is not part of this run.
