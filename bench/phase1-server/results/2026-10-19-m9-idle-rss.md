# M9 idle RSS with every role and the allocator of the musl binary, 2026-10-19 (Linux)

Verdict: PASS (the static musl binary with jemalloc idles at 85.31 MiB at most against 95.37 MiB, with the roles controller, probe and dns)

Measurement M9 of the Phase 1 plan (section 8), run for the change of the global allocator of the static musl binary that ships. musl's own malloc made the replicated store's write path four to seven times slower than on Windows (M18 and M20 of Phase 2), and the owner decided on 2026-10-19 to give the musl build a faster allocator provided OPS-15 still holds. Two allocators were tried: mimalloc, which fails OPS-15, and jemalloc with its options compiled in, which passes and is the one the binary ships with (`crates/tenko/src/main.rs`, `.cargo/config.toml`). Unlike the earlier M9 runs, which ran the controller alone, every run here has every Phase 1 role plus the dns role (`controller,probe,dns`; `dhcp` is not implemented). The speed side of the change is in [../../phase2-dns/results/2026-10-19-m18-zone-load.md](../../phase2-dns/results/2026-10-19-m18-zone-load.md) and [2026-10-19-m20-signing.md](../../phase2-dns/results/2026-10-19-m20-signing.md).

## Summary

100 MB is read as 100,000,000 bytes, which is 95.37 MiB. Memory figures are MiB, from `/proc/<pid>/status`. "Ready" is the sample when the server is ready, before setup; its VmHWM is the start-up peak. "Peak" is VmHWM after setup, login and the 200 prefixes. Idle: 21 samples over 600 s.

In short:

- **jemalloc as configured costs nothing at idle.** Its idle median is 84.74 MiB against 85.61 MiB for musl's malloc, its anonymous memory at the end 1.2 MiB more (22.08 against 20.85 MiB), its start-up peak 2.2 MiB more (91.68 against 89.50 MiB). One background thread more (43 threads against 42).
- **mimalloc fails.** With its defaults it asks the kernel for transparent huge pages on its arenas (`madvise(MADV_HUGEPAGE)`; WSL2's THP mode is `madvise`, so the request is granted) and returns freed memory only when the thread that owns it allocates again. At ready 192 of its 195 MiB of anonymous memory are huge pages (`AnonHugePages` in `smaps`), and nothing is given back during the idle phase. Turning both off through the environment (c) comes close but still crosses the line: the purge delay has no compile-time setting, so in the binary it needs `unsafe` code (`mi_option_set`) or the environment.
- **The jemalloc options matter.** A decay of 1000 ms (e) keeps the start-up burst for a second and leaves 41 MiB of anonymous memory at ready; immediate purging (d) with two arenas passes but with 2.7 MiB of margin at the first idle sample; one arena, one background thread and a 1 KiB thread cache limit (f) bring it to the level of musl's malloc. (f) is also the variant with the least memory under load (M18, M20) and with every M20 change under one second.

## Method

As in [../README.md](../README.md), with the roles option that `m9-idle-rss.sh` gained for this run: a fresh data directory, the shipped defaults (`internal_ca` TLS, profile `home`, the platform key provider, which falls back to a plain key file for a non-root user in WSL, one UDP worker per CPU for the dns role), `hibp.online = false`, first-run setup and login with the CLI, 200 prefixes with `tenko prefix create`, 600 s idle with a sample every 30 s, then `SIGTERM`. The dns role answers on a loopback port because port 53 needs privileges.

```
bash bench/phase1-server/m9-idle-rss.sh --binary <bin>/tenko-<variant> --roles controller,probe,dns --port <port> --dns-port <port> --outdir <dir>/m9-<variant>
MIMALLOC_PURGE_DELAY=0 MIMALLOC_ALLOW_THP=0 bash bench/phase1-server/m9-idle-rss.sh --binary <bin>/tenko-mimalloc ...      (c)
```

The probe table: a node with the same roles and configuration but no setup, its `/proc/<pid>/status` and the sum of `AnonHugePages` in `/proc/<pid>/smaps` read 10 s after ready.

Two runs at a time shared the machine (the baseline with (b), (d) with (e), and (f) with an M18 run that started after its data creation); memory figures do not depend on that, and each idle phase was flat after the first minute.

## Results

Every run created 200 of 200 prefixes without failures (15.6 to 16.4 s), was ready after 0.8 to 1.2 s, and stopped on `SIGTERM` with exit status 0.

## Verdict

M9 is met on Linux by the binary that ships: the static musl build of `a5bc069` with jemalloc idles at 85.31 MiB at most (89.5 MB) with the roles controller, probe and dns, 10.1 MiB under 95.37 MiB, and at the level of musl's own allocator (86.60 MiB at most). mimalloc, the allocator first chosen, fails OPS-15 and is not used.

## Caveats

- Linux was measured inside a WSL2 VM, not on bare metal. A host whose transparent huge pages are `always` (the default of some distributions) would give mimalloc huge pages without asking; jemalloc's options here do not use huge pages.
- One run per variant; RssFile moves by up to 8 MiB between runs of the same binary (2026-10-16), which is the size of the margin of (d) and the failure of (c).
- The data set is CLI-created prefixes; the dns role serves no zones during M9.
- Raw output (CSV, summaries, redacted server logs) is in a directory in WSL; it is not committed.
