Mockup notes: dashboard

Try it: press 1 to 4 or use the control above to switch between the cluster and a node, click a node in the queries per second tile, hover every line and bar, tick Tables, press P to pause, flip Mockup scale in the status bar to Enterprise to see the same tiles at 1.3M queries per second, then flip the theme.

  1. Decided: queries per second is a number with SI suffixes (1.2K, 48K, 1.3M); the same formatter is used everywhere a number can grow.
  2. Switching scope swaps every number in place without navigating, and clicking a node in the by-node list does the same (click it again to return to the cluster). Should the last scope be remembered per user, and do you need a side-by-side compare of all three nodes?
  3. Raft and store figures show their age and have a refresh button, because the architecture caches them and updates them every 30 s. Is that honesty worth the extra text, or should the whole page look equally live?
  4. Response codes use categorical color, not status color, because NXDOMAIN at 8% is normal on a home network and a status color would call it a fault. Should SERVFAIL alone raise an alarm above a set share, for example 1%? The 0.3% REFUSED slice gets a 3 px minimum so it stays visible; hover a legend number or open the table for the exact figure.
  5. Alarms: the pool alarm is one fixed 80% for every scope, and any dnstap drop in the last hour raises a warning. Should the pool threshold be editable per scope, and is "any drop" too sensitive? The attention line at the top repeats the tile warnings so they are visible without scrolling. Keep it or drop it?
  6. The page stops updating while you hover or focus a chart or the table, so a tooltip never moves under the pointer, and it also has an explicit Pause. Is pausing on hover right, or should it only pause on request?
  7. In memory shows 96 MiB against a 100 MiB idle target, but OPS-15 says 100 MB and 96 MiB is 100.7 MB. Which unit should the requirement and the meter use?
  8. This view keeps only the last 60 s in memory (OPS-20), so there is no history. Should it link to a Grafana or Prometheus view when one is configured, or is Open /metrics enough for a first release? The latency and lease lines have no table of their own; their numbers sit in the table behind the queries per second tile. Is that acceptable?
