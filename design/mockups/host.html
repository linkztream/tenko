Mockup notes: host detail

Try it: pick a mode and read the preview, switch Lock on, press Fix DNS or Accept observed, Copy password, Scan now. Press Esc to close the panel, Shift+Enter for the full page, or use the scene switcher in the status bar.

  1. Panel layout: this is one scrolling column with a sticky jump row (Identity, Mode, Intent, Scan, Remote, DNS, History). The alternative is tabs (Overview, Observation, History, DNS and DHCP). Scrolling keeps every fact one scroll away and nothing hidden, but History sits nearly three screens down. Tabs keep each view short but hide the differences and the audit trail behind a click. Which do you want for daily use?
  2. The panel covers the sources and flags columns of the grid beneath it. Should it instead push the grid left and drop those columns, so the rows stay fully readable beside the panel?
  3. Every mode change shows an inline preview with Apply and Cancel, even when nothing outside Tenko changes (for example static to unmanaged). Keep the preview every time, or skip it when no DNS, DHCP or network step is involved?
  4. Lock applies at once, lists what it stops and offers Undo. Should locking ask for a reason that appears in History, or stay one click?
  5. Intent and observation lists all fields and shows one value where they agree. Would you rather open on Differences only, with All fields one click away?
  6. The extra SLAAC address uses the same amber as the stale PTR record and is labeled informational. Should informational items be neutral and never count toward the header flag and the grid flag?
  7. Copy password reveals and copies in one click, then shows the audit notice. Should a reveal ever ask for a reason or a re-entered password, and if so, only under stricter security profiles?
  8. Esc closes the panel and, from the full page, returns to the panel. Should J and K also step to the previous or next host while the panel is open, so you can read down a range without closing it?
