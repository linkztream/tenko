Design spike: the core views

Clickable mockups of the Tenko DDI interface, for review before any SolidJS component is written. They share one token file and one set of components, so what you see here is the product's look and its interaction model, not the final code.

Work through them in order. Each page has a Mockup notes button at the right end of the status bar with the open questions for that view, and some have a dashed Mockup scene switcher for states that would otherwise need live data. The full question list is in REVIEW.md.

  1. First-run wizardwizard.htmlFrom an empty node to a running one: security profile (pick Lab to see the warning), first administrator with passkey, data directory with the rotating-disk check, roles. Uses the two-tone fox.
  2. Sign-insignin.htmlPasskey first, password as fallback, the progressive delay after failed attempts. Uses the two-tone fox; single sign-on comes later.
  3. Dashboard (start page)dashboard.htmlCluster and per-node health: queries per second with SI suffixes so tiles never grow, latency, cache, response codes, DHCP pools, store size, replication and dropped log records.
  4. Shell and IPAMshell-and-ipam.htmlThe application frame and the address grid for 192.0.2.0/24: prefix tree with networks and SSIDs, filter bar, source badges, inline editing, keyboard focus. Opens mid-gesture: three hosts dragged onto the IoT network. Try dragging rows yourself.
  5. Host detailhost.htmlOne host as a side panel over the grid and as a full page: identity, mode, lock, intent next to observation with the differences marked, ports, remote access with audited password copy, history.
  6. Move jobmove-job.htmlMoving five devices to IoT: the preview per device (wireless clients move to the SSID that carries the VLAN), the confirm bar with parallelism and a timeout derived from the lease, the running job, automatic rollback, and the jobs list.
  7. Topologytopology.htmlThe network as a layered map with generated VLAN colors, SSIDs on the access points, a hover card, what is connected to this port, a path highlight and filters, plus how it scales to thousands of nodes and 150+ VLANs.
  8. Discovery and reconciliationreconciliation.htmlThe two finding views as built: Discovery lists findings of every kind grouped by severity with a default action per row, and the per-network Reconciliation view shows what intent, lease, DNS and scan say, with a check glyph on the truth that wins. Both share one table, one set of 28 px rows and one side panel. Switch the Mockup scene in the status bar; open the Info group.
