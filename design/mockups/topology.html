Mockup notes: topology

Try it: hover a node (ap-hall lists its wireless networks), click a port badge (14 or 1), click the Home-IoT label under an access point, click desk-01 and press P, click a VLAN chip to show only that VLAN (Shift+click adds or removes one) and watch the colors change, set Color by to Selected VLANs or Site, turn Patterns on, type "port 14" in the search, switch the layout to Radial, zoom out below 75 % and click the lab-k8s node. The three scenes in the status bar jump to the interesting states.

  • Decided: VLAN colors are generated for the VLANs in view, with no fixed cap. A label on every edge group, a legend with the contrast of each color and a Patterns toggle are the backup, so color is never the only carrier.
  • Decided: hosts are moved by dragging them onto the IPAM prefix tree. The map has no drop targets; it only selects, highlights and opens.
  • Owner’s request: wireless networks (SSIDs) are IPAM objects, read from UniFi with their VLAN; access points are labeled with their SSIDs.
  1. Layered is the default because a home or branch network is a tree. Real sites add redundant links and aggregation, which a strict tree hides. Keep Layered as the default and offer Radial only as an overview, or default to whichever fits the data?
  2. Routers, switches and APs are drawn neutral because they carry several VLANs, and only clients and VMs take a VLAN color. Trunk edges list the VLANs they carry as text ("10, 20, 40"). Is the list enough, or should a switch also show a small stack of VLAN swatches?
  3. Filters dim, they do not hide, so positions never move. At a few hundred nodes dimmed clutter becomes noise. Dim up to a limit and then hide automatically, or let the user choose? Related: with Color by Selected VLANs the same chips pick colors instead of filtering. Is one set of chips for both jobs clear?
  4. Path highlight always ends at the gateway. Should it also work between any two nodes (Shift+click a second node), for questions like "how does lab-ws01 reach web-dmz"?
  5. Port numbers sit on every wired edge. Always visible helps the "which port is that" question but adds noise. Show them always, only on hover and selection, or only above a zoom level?
  6. The port panel is read only and links to the job that last changed the port. Should it also offer "change port profile", or must every L2 change go through the move preview?
  7. Click selects and the bar offers Open host (ShiftEnter). Would you rather double-click to open the host and keep single click for select only? Clicking a switch opens its port list automatically; is that too eager?
  8. Wireless edges now carry the SSID name and each access point lists its SSIDs. Should band and signal strength also sit on the edge, or stay in the hover card and the SSID panel? Should an SSID nobody uses yet (Lab-Test) stay on the access point?

How it scales to thousands of nodes

This page is a static SVG of 23 nodes, for review only. The product behavior is below; the controls on this page are the same ones the product keeps.

  • Clustering. A switch's clients collapse into a count bubble such as "24 clients" and expand on click. The lab-k8s node shows the pattern (select it, then Expand).
  • Search first. Type a host, IP, MAC or port, press Enter to jump to the node, then show N hops around it. Nothing needs the whole map on screen.
  • Focus mode. The selected node plus 1 to 2 hops, everything else removed and the view refitted. This is the default way to read a large site.
  • Level of detail. Labels only above a zoom threshold (zoom out below 75 % and below 50 % to see it). Color and shape stay at every zoom level.
  • 150 or more VLANs. Hues are generated for the VLANs in view, which stays distinguishable up to roughly a dozen. Beyond that, color by selection (only the VLAN chips you select get color, the rest neutral gray) or by site (VLANs neutral). Labels on every edge group and the Patterns toggle (a dash style per VLAN) remain as backup, and the legend lists only what is in view and counts the rest with an SI suffix (1.2K).
  • Rendering. WebGL with sigma.js and graphology, and an ELK layered layout, chosen in the phase 1 spike. Plain SVG gets sluggish in the low thousands of elements and WebGL stays smooth well beyond that, so the spike decides by measuring.
  • Position memory. Layout is computed once, then positions are stored per user and site, so the map does not reshuffle between visits. New nodes are placed next to their neighbors, and "Reset layout" is the only thing that recomputes.
