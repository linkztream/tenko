## Deployment packages (added on the owner's decision, 2026-10-19)

The owner's plan: every current Tenko machine (the home node in an LXC, the measurement VMs to come) is a throw-away lab; once the product is stable and the update path proven, the production cluster is set up from scratch on clean machines. That start must be one command, so the installers get priority now and are tried on the measurement VMs as they are set up, rather than tested again at the end. Decided with it: no code-signing certificate for now (an OV certificate costs about 220 USD a year plus a hardware token, an EV one 290 to 500 USD, Azure Artifact Signing about 10 USD a month but only for organisations in the EU); the MSI ships unsigned with the SmartScreen notice documented, and the release workflow signs when a signing secret is present, so a certificate later is a configuration change. Ansible waits for Phase 5 (a thin role over the installer's unattended mode, worth it for a fleet, not for one node).

## Conventions

- Every figure is a single-node figure (plan section 2.10); Linux figures come from the static musl binary.
- Builders run as in Slice 3: local Opus or Sonnet agents in their own worktrees with their own `CARGO_TARGET_DIR` under `F:\`, briefed by the lead; the lead gates in `F:\tenko-verify` and squashes onto `main`.
