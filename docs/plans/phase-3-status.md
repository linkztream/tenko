# Phase 3 status

The working state of Phase 3 (DHCP) of Tenko DDI: which work packages of [phase-3-plan.md](phase-3-plan.md) are merged, what each delivered, what is open, and the push state of `main`. Phase 2's state stays in [phase-2-status.md](phase-2-status.md) until its exit document (WP6.5) is merged; this file took over for Phase 3 when WP7.1a merged on 2026-10-21.

## Plan and decisions

The plan was drafted on the night of 2026-10-21 by a local Opus builder and merged as `a2cb543` with ADR 0019 (the DHCP data model and lease path) and ADR 0020 (DDNS from DHCP), both Proposed. The owner decided P3-Q1 to P3-Q11 the same night (leases as rows in the replicated store committed before the ACK, with an asynchronous publication model as the measured fallback; failover pairs and the chaos test to Phase 5; DHCPv6 as the last slice; one model where a scope is an IPAM prefix with a DHCP policy and a reservation is the IPAM reserved host; the reference gateway relays every network to one node; DDNS through the in-process update path with the existing `Origin::Dhcp`; conflict detection through the probe role capped at 300 ms; the observation written in the lease's commit; PXE and classes in Slice 8; the Kea export in Slice 9; the first test drive between the two lab VMs). Open for the owner: P3-Q12 to P3-Q18 (classes as Windows-style conditions, lease history as a bounded table with retention per profile, the behaviour while the store refuses writes, an offline fingerprint table, full PXE with ProxyDHCP last, the Kea export scope, the gateway relay checked by hand) and the threshold of the Q1 fallback (the plan proposes under 1,000 exchanges per second, or p99 above 100 ms at 1,000 per second, on M26 or M28). The plan notes that the Q1 decision contradicts DHCP-07, a line of ARCHITECTURE.md and point 4 of ADR 0002, and lists the text changes in its section 7; how ADR 0002 is marked is the lead's call. Risks run R55 to R71.

The data-plane HA plan (`docs/plans/ha-plan.md`, with ADR 0025, Accepted on 2026-10-25) was written on 2026-10-25 by a background Opus agent and merged as `c7d045e5` after the docs gate, on the owner's decision that HA and identity are to be done right from the start: a failover pair after the ISC draft with the lease committed to the serving node's own store before the ACK and published to the controllers after, dns and dhcp nodes fed by node sync into a node store, decisions HA-Q1 to HA-Q15 decided by the owner on 2026-10-25 as recommended and ADR 0025 Accepted, Slice 12 (WP12.0 to WP12.8) after WP9.5 and before Phase 4 (HA-Q1).

The identity plan (`docs/plans/identity-plan.md`, with ADR 0026, Accepted on 2026-10-25) followed the same day, merged as `9278e0b8` after the docs gate: GSS-TSIG from Windows accepted in pure Rust (the sspi and picky-krb crates, a spike in WP13.0 deciding), a pre-staged AES-only computer account whose password Tenko takes over and rotates, ownership per name with the Windows rules, OIDC and LDAP sign-in with group mapping and Kerberos web sign-in, no SAML, RADIUS or TACACS+; decisions ID-Q1 to ID-Q18 decided by the owner on 2026-10-25 as recommended, ID-Q13 with the addition that LDAPS is set up in the UI by importing the certificate chain of the domain controllers (fetch, confirm the fingerprints, pin; a PEM file or the system trust store as alternatives; a clear-text warning on plain LDAP), and ADR 0026 Accepted, Slice 13 (WP13.0 to WP13.8) in Phase 4 (ID-Q10).

The UI plan (`docs/plans/ui-plan.md`, 2026-10-26) turns the owner's design proposal of that day into the work packages U1 to U8 (the findings index with the label catalog and the guard rail against network and broadcast addresses first, then the shell, the dashboard, reconciliation with Discovery as the findings list, jobs, IPAM networks with the address map and the saved table layouts, topology with the SSID view, and the DNS cache), with the design guide's ten principles, the severity and paired `-on` tokens, and TGL-38 (a second person's approval under Hardened, built in Slice 13); the owner accepted the lead's decisions UI-Q1 to UI-Q11 the same day. It adds no requirement and no change to the product yet.

ADR 0029 (`docs/adr/0029-an-agent-tool-with-guard-rails.md`, Proposed, 2026-10-29) records the owner's decision that Tenko ships its own tool for language-model agents, `tenko mcp` in the CLI over stdio, so that the safe way to connect an agent is the easiest one ("it should be easy to do the right thing"): a curated set of bounded read tools with a fixed note that network text is data, no tool that executes a change (a write tool creates a job with a preview and a manual step a person approves in the interface), an anonymisation mode on by default, an agent token type, the audit principal `agent via <user>`, and TGL-39 (agent writes through jobs; Hardened off). Drafted by a Sonnet agent, proofread by the lead (six corrections: the ADR 0023 reference, the deletion rule, the token's renewal, a call budget for a looping agent, the fuzz target's scope, a threat-model goal), merged as `ef9ac9ba` after the docs gate. Built after U5 and U6.

ADR 0030 (`docs/adr/0030-durability-classes-of-the-lease-path.md`, Accepted, 2026-10-30) records the two durability classes of the lease path that WP9.6 built after the lab run of 2026-10-30 found the shipped 0.0.8 at a fifth of 0.0.2's lease rate: the lease row and its client index entry are committed before the ACK, everything derived from them follows within a second from an asynchronous writer in the store's background class; snapshots are due by entries, the group commit is bounded, and the log records and the snapshots are compressed. ADR 0031 (WP9.7, decided by the owner on 2026-10-31) takes the next step: the lease table itself is the DHCP observation source, so no fact rows are written for leases, the history row is lean and the lease row carries its grant time; the E22 figures are re-measured on that build.

The UI plan's eight packages were all merged by 2026-10-29 (U1 `203ca03a`, U2 `255775a8`, U3 `71510c27`, U8 `2857e645`, U4 `ef3933e0`, U7 `d8b3b47e`, U5 `3b1947dd`, U6 `11aee047`; the rows are in `phase-2-status.md`). The first load ended at 77.9 KB gzip against the 76.9 KB it started from, within the +1 KB per merge rule, without the one-time raise the owner allowed. Left open from the packages: a class and a role field in place of U7's tags, a per-prefix SSID panel, a column chooser on the zones and leases pages, a Playwright spec for the topology and the SSID view.
