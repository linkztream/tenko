# Test health, November 2026

A review of how far the project's tests can be trusted, written on 2026-11-11 by reading the
code, the CI workflows and the saved logs of the merge gate. Nothing was built and no suite was
run for it: every claim names a file and a line, or a log. The measurements that reading cannot
give (coverage, repeated runs under load) are planned in the last section.

Terms used throughout:

- A **flaky test** passes and fails on the same code. Here it almost always means the test
  depends on how fast the host is.
- The **gate** is the full check that runs on the lead's Windows workstation before every merge:
  `cargo nextest run --workspace --all-features --locked`, the UI unit tests (`vitest`), the
  end-to-end tests (Playwright, a real browser against a real `tenko serve`), the script tests,
  clippy, the traces and more. **Push CI** is `.github/workflows/ci.yml` on GitHub-hosted runners.
  **Weekly CI** is the same file's `schedule` jobs (Sunday 03:17 UTC).
- **nextest** runs each Rust test in its own process. Its configuration is
  `.config/nextest.toml`, which states the rule this review applies: no retries; a test that
  fails under load has a cause, in the product or in the test.
- A **paused clock** is tokio's test mode (`#[tokio::test(start_paused = true)]`) in which time
  moves only when the test says so (`tokio::time::advance`). An **injected clock** is a `Clock`
  value the product takes as a parameter, so a test can hand it a `MockClock` and set the time.
  A **seam** is the place where the product takes such a value instead of reading the wall clock
  itself.
- A **vacuous pass** is a test that returns before it asserts anything, so it is green whether
  the property holds or not.
- A **test double** (mock, fake) stands in for a real component. A test that asserts on what the
  double itself returns proves nothing about the product.
- A **fuzz target** feeds random bytes into a parser to find crashes, hangs and unbounded
  allocations (`fuzz/fuzz_targets/`). The fuzzing engine is **libFuzzer**, driven by
  `cargo fuzz`.
- A **lazily loaded** page or module is a piece of the UI's code that the browser fetches and
  compiles the first time it is shown, not at start; the first test that shows it pays that time.
- A **doctest** is a code example in a Rust doc comment that `cargo test --doc` compiles and runs.
- A **JUnit report** is an XML file, written by the test runner, with every test's result and
  duration.
- **mTLS** (mutual TLS) is TLS in which both ends present a certificate; the cluster's nodes and
  controllers use it.
- IDs such as `DNS-11` are requirement rows of `docs/REQUIREMENTS.md`; `E14` is an exit criterion
  of a phase plan and `M23` a measurement of it (`docs/plans/`). The **lead** merges work after
  the gate; a **builder** is whoever carries out one repair package. Packages `T1` to `T12` are
  defined in section 8.

## 1. Host-dependent tests

A test whose result depends on the wall clock or on the speed of the host. Six classes; each
finding has one primary class.

| Class | Meaning |
|---|---|
| sleep-sync | A fixed sleep used as synchronization: sleep, then assert on state another thread, task or process should have produced by then. Also a sleep that lets a real-time expiry happen. |
| deadline | A time-out or wait limit that load can exceed. Under 5 s is high risk, 30 s or more on a millisecond operation is low. |
| duration-assert | An assertion on a measured duration or rate ("under 100 ms", "1,000 records within 1 s"). |
| count-assert | An assertion on a count that timing changes: rounds, retries, restarts, ticks in a window. |
| calendar | A dependence on the date, the time zone or the locale. |
| host-env | A dependence on a free port, on hash map or directory order, on the number of cores, on the host's interfaces or tools. |

### 1.5 The date that breaks eight tests

`crates/tenko-ipam/src/observe/dhcp/tests.rs:26-31` builds every fixture time from
2026-10-22T08:00Z, and the leases end an hour later. `LeaseFacts::build`
(`crates/tenko-ipam/src/observe/dhcp.rs:337`) drops rows that ended more than the retention ago
by `Timestamp::now()`, and `LeaseFacts::fact` (`:592`) reads `Timestamp::now()` too. The default
retention is 30 days (`crates/tenko-ipam/src/observe/mod.rs:75`; the check is `dhcp.rs:275`). So from **2026-11-21T09:00Z** these tests lose their
rows and fail:

`the_observation_id_is_stable_for_a_binding_and_changes_with_a_new_grant_or_another_mac` (`:713`),
`the_facts_are_found_by_mac_address_ip_address_and_name` (`:836`),
`the_view_is_built_from_the_rows_that_exist` (`:911`),
`a_build_reads_more_rows_than_one_page` (`:952`),
`the_follower_builds_at_start_and_follows_a_lease_change` (`:1069`),
`a_deleted_lease_row_leaves_the_view` (`:1114`),
`a_compacted_journal_rebuilds_the_view_from_the_tables` (`:1350`),
`a_lagging_stream_rebuilds_the_view_from_the_tables` (`:1358`).

Commit `4f0c6574` fixed the same cause in `LeaseFacts::ensure` on 2026-11-09 and left these two
calls. The fix is a seam: `build` and `fact` take the time from their caller, as `facts(now)`
already does.

## 3. Tests that prove less than their name

The check: a test name states a property. The test passes the check when an assertion exists
that fails if that property is false, and the test sets up the situation the name describes.
**WEAK**: an assertion covers part of the named property, or is looser than the name (an
`is_err()` where the name says a specific refusal, so an unrelated error passes too). **FAIL**:
no assertion fails if the property is false.

The sample was chosen by risk: every test, in file order, of the authentication and lockout,

### Standing rules for a new test

What a new test must not do, one rule per class of section 1, checked by `scripts/test-lint.mjs`
in the gate and in push CI (Node's standard library only, like `scripts/spelling.mjs`; an
exception carries a comment `test-lint: allow <rule> <reason>` on the line):

1. No sleep as synchronization: wait for a named condition with the shared helper, or use a
   paused clock. A sleep is allowed inside the shared helper and in pacing loops that the comment
   explains.
2. No wait limit below 10 s unless the limit is the subject of the test.
3. No assertion on a duration or a rate outside `bench/` and `#[ignore]`d measurements.
4. No count that depends on timing; assert the outcome.
5. No `now()`, `SystemTime::now()`, `Date.now()` or `new Date()` in an expectation, and no literal
   date compared with the wall clock: the product takes the time as a parameter or a `Clock`.
6. No port found by binding and dropping; no ordered comparison of a hash map or a directory
   listing; no dependence on the core count.
7. No `retries` in Playwright and none in nextest; no `only`.
8. Every `#[ignore]` names who runs it and when; every early `return` in a test names the job that
   meets its condition.
9. A refusal is asserted by its code, not by `is_err()`.

Clippy cannot express most of these for test code alone (`clippy.toml` applies to product code
too), which is why the rules live in a script. The script starts from a baseline of today's
findings and fails on any new one.

Should the gate run the suite a second time under artificial load? Not the whole suite: the
gate already runs on a loaded machine, and a second full run would add four to eight minutes to
every merge. Two targeted runs instead: (a) the gate runs the tests a commit adds or changes
five times beside a load generator (a small script of our own that keeps every core busy), so a
new flaky test is stopped at the door; (b) a weekly run of the whole suite five times under load
on the workstation, with the JUnit files kept, whose failures become rows of this document.

## What the measurements will add

Two measurements wait for the next phase, when the machine is free and the coverage tool is
installed (it is not in the repository today):

**Coverage** (which lines and branches the tests execute):
`CARGO_TARGET_DIR=F:/cargo-target-coverage cargo llvm-cov nextest --workspace --all-features --locked`,
then the same without `--all-features`, once on Windows and once on Linux (the Windows-only and
Linux-only tests of section 2.3 cover different code), with an HTML and an LCOV report. Expected
to show: low coverage in the error branches of the network parsers that no fuzz target reaches

each way. Expected to show: which of the 100 high-risk rows of section 1 fail first (the
classification is confirmed or corrected per test), the ratio of each test's duration to its
