# The -max_len of every fuzz target: the largest input the parser can meet in production, plus
# the control octets the target reads in front of it. The weekly smoke (.github/workflows/ci.yml,
# job fuzz-smoke) and the security round (deploy/security/fuzz.sh) read this file and pass the
# number with -rss_limit_mb=2048 -malloc_limit_mb=1024; a target without a line here fails both.
#
# Rule: where production accepts more than 64 KiB (an HTTP body of megabytes, a 32 MiB gRPC
# message), the line says so and the target gets 65,536 octets plus its control octets, which is
# enough to reach the parser's own limits; a target that needs more for a branch of its own gets
# that and says why. Format: the target, the number, then where the number comes from (free text
# to the end of the line). Keep the targets in the order of `cargo fuzz list` (sorted).
#
# target                 max_len  where the number comes from
